# 过敏原标签复核台（FastAPI + SQLite + React）

模拟食品企业的过敏原标签复核场景：配方可引用原料或更早的子配方，原料绑定供应批次；
复核台支持提出替代原料、查看每个过敏原标签经哪些引用路径传播，并以**两名不同审核者
对同一不可变配方快照确认**作为放行条件。

## 业务规则（均有测试覆盖）

| 主题 | 规则实现 |
| --- | --- |
| 不可变快照 | `recipe_versions` + `components` 一经写入不再更新；组件行带 `material_labels` 过敏原快照与 `content_hash` 指纹。后续修改原料绑定不影响旧版本 |
| 多级引用 | 配方只能引用**更早的**已存在版本；服务端 DFS 展开标签/批次传播路径，解析器另有循环引用检测兜底 |
| 标签传播 | `GET /api/versions/{id}/graph` 返回每个过敏原的全部引用路径（如 招牌蛋糕 › 戚风蛋糕胚 › 卡仕达酱 › 全脂牛奶[B-MILK-2609]） |
| 双人放行 | 同一版本需 2 个**不同**审核者；`(版本,审核者)` 唯一约束阻止同人重复确认；第二人确认前重新做“活体检” |
| 审批失效 | 第二次确认前配方产生新版本 ⇒ 旧快照上的半成品审批标 `stale`，旧快照 409 不可放行；新版本需重新双人确认 |
| 失效批次 | 已召回 / 已过期（按业务日期）批次阻止进入新版本、阻止放行；第一次确认随之失效 |
| 批次召回 | 不修改任何既有放行记录（`status/released_on/approvals` 原样保留），只把所有（含多级传递）命中版本标 `needs_review=1`、返回传播路径；未完成审批标失效；新版本须重新放行 |
| 替代原料 | 提案只针对当前版本；采纳时以旧快照为蓝本生成**新不可变版本**（乐观锁检测并发替换），竞争失败的提案标 `superseded` |
| 并发 | 全部写操作在 `BEGIN IMMEDIATE` 事务内裁决（SQLite WAL + busy_timeout），审批竞争/替换竞争有线程级测试 |
| 同源视图 | 页面差异、标签清单、JSON/CSV 导出都按同一 `version_id` 从服务端取，带同一 `content_hash` |

## 目录

```
app/            FastAPI 后端
  db.py           连接/Schema/迁移（WAL、BEGIN IMMEDIATE）
  service.py      业务核心：快照、传播图、活体检、双人审批、召回、提案、差异
  serializers.py  统一版本视图序列化（页面/导出共用）
  schemas.py      Pydantic 模型
  seed.py         模拟数据（8 类过敏原、9 种原料、10 个批次、3 个配方 4 个版本）
  main.py         API 路由，生产模式挂载 frontend/dist
frontend/       React + Vite 复核台（标签传播/差异/审批/提案/召回页签）
tests/          26 个 pytest 用例
```

## 运行

```bash
pip install -r requirements.txt
python -m app.seed                         # 灌入模拟数据（data/allergen.db）
python -m uvicorn app.main:app --port 8000 # 已构建时直接访问 http://localhost:8000

# 前端开发模式（热更新，代理 /api -> 8000）
cd frontend && npm install && npm run dev
```

## 联动替代单

替代单选择一组当前产品版本，按原供应批次指定替代原料及有效批次。预览不改变配方，采纳后生成新的不可变版本。范围包括产品引用链上使用该批次的子配方；同一子配方在同一单中只有一个替代结果，不涉及替代的分支沿用原版本。受影响引用必须都是各配方当前版本，否则预览拒绝。预览后受影响配方变化、替代批次失效或采纳失败时，整单不生效。采纳成功可重复查询或提交相同单，不重复创建版本。原放行记录保留，新版本重新审批。

POST /api/replacements/preview 接收 roots（版本编号列表）、targets（原批次编号到 material_id/batch_id 的对应表）、created_by。POST /api/replacements/{id}/apply 采纳，GET 同路径查询。页面“联动替代”可预览及采纳。
